# Скачай

Android-приложение для сохранения видео и фотографий. Откройте публикацию в YouTube, Instagram или TikTok, нажмите «Поделиться» и выберите «Скачай».

**[Скачать приложение для Android](https://github.com/donatefrost-cell/skachay-android/releases/latest/download/app-release.apk)**

Поддерживаются телефоны Android 8 и новее с процессором ARM. После скачивания откройте APK; если телефон попросит разрешить установку из браузера или файлового менеджера, разрешите её в появившихся настройках. Затем откройте «Скачай» и выберите режим «Просто».

Для обычного скачивания вход в аккаунт не нужен. Доступность отдельных публикаций зависит от ограничений самих сервисов; закрытые или удалённые публикации могут быть недоступны.

В приложении есть простой и расширенный режимы, выбор качества YouTube, сохранение отдельной аудиодорожки и субтитров, загрузка плейлистов, пакетная вставка ссылок, ярлык и плитка быстрых настроек, а также недавние файлы с поиском и фильтрами. Очередь сохраняется локально: загрузку можно поставить на паузу, продолжить или отменить; после принудительного завершения она появится как прерванная и её можно повторить. Повтор после перезапуска начинает передачу заново. В недавних можно искать, фильтровать и выбрать несколько файлов для отправки; удаление подтверждается и его можно отменить из уведомления внизу экрана.

## Сборка

Потребуются JDK 21 и Android SDK с платформой API 37. В корне проекта выполните:

```sh
./gradlew testDebugUnitTest assembleDebug
```

На Windows вместо `./gradlew` используйте `gradlew.bat`. Готовый тестовый APK появится в `app/build/outputs/apk/debug/`. Его можно установить на телефон с Android 8 или новее.

После отправки проекта в GitHub сборка будет запускаться автоматически; APK появится на странице запуска в разделе **Artifacts**.

Compose screenshot previews покрывают главный экран, очередь загрузок, карточку предпросмотра, выбор качества, загрузку сведений, длинные названия, аудиовкладку, расширенные параметры, настройки и диагностику. Для главных экранов, выбора и разделов настроек есть светлая и тёмная темы при масштабе 100%, 150% и 200%. GitHub Actions генерирует все сценарии из `ScreenScreenshotTests.kt` и прикладывает PNG в артефакт **skachay-screenshots**. На эмуляторе также проверяются восстановление очереди и число уведомлений. Архивы находятся в разделе **Artifacts** соответствующего [запуска сборки](https://github.com/donatefrost-cell/skachay-android/actions/workflows/android.yml).

## Как подготовить свой ключ для выпусков

Подписанный выпуск позволит устанавливать последующие версии поверх предыдущих. Ключ нужен только вам: сохраните файл ключа и пароли в надёжном месте и сделайте резервную копию. Потеряв ключ, вы не сможете подписать следующую версию как обновление уже установленного приложения. Не добавляйте ключ или пароли в репозиторий.

Для этого проекта ключ владельца находится только в закрытой локальной папке `private-signing`, а секреты для автоматической сборки — в настройках GitHub Actions. Владельцу нужно сохранить защищённую резервную копию этой папки. Инструкция ниже предназначена для тех, кто собирает собственную копию приложения со своим ключом.

1. Установите JDK 21 и убедитесь, что переменная `JAVA_HOME` указывает на папку JDK.
2. Откройте PowerShell и создайте ключ за пределами папки проекта:

   ```powershell
   & "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -alias skachay -keyalg RSA -keysize 3072 -validity 10000 -storetype PKCS12 -keystore "$env:USERPROFILE\skachay-release.p12"
   ```

3. Придумайте пароль и ответьте на вопросы программы. В этом примере имя ключа — `skachay`, а пароль ключа совпадает с паролем файла. Файл `skachay-release.p12` появится в вашей пользовательской папке Windows.
4. Откройте репозиторий на GitHub → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**. Добавьте четыре секрета:
   - `SKACHAY_KEYSTORE_PASSWORD` — пароль файла ключа;
   - `SKACHAY_KEY_ALIAS` — `skachay`;
   - `SKACHAY_KEY_PASSWORD` — тот же пароль;
   - `SKACHAY_KEYSTORE_BASE64` — содержимое файла ключа, преобразованное в строку. Для этого выполните команду ниже и вставьте скопированное значение в секрет:

   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\skachay-release.p12")) | Set-Clipboard
   ```

   После добавления секрета очистите буфер обмена командой `Set-Clipboard -Value ''`. Base64 не шифрует ключ: не отправляйте эту строку в чат и не публикуйте её.

## Как выпустить и установить APK

Когда все секреты добавлены, создайте новый возрастающий тег в PowerShell из папки проекта. После выпуска `v0.3.10` следующим номером будет `v0.3.11`:

```powershell
git tag v0.3.10
git push origin v0.3.10
```

GitHub Actions запустит тесты, соберёт подписанный APK и добавит его в **Releases**. Для каждого следующего выпуска используйте новый возрастающий номер, например `v1.0.1`, затем `v1.1`.

Скачайте `app-release.apk` из выпуска на телефон и откройте файл. Android может предложить разрешить установку из этого браузера или файлового менеджера — включите разрешение в открывшихся настройках и вернитесь к файлу. Если ранее была установлена тестовая debug-версия с другой подписью, перед установкой выпуска её потребуется удалить вместе с данными приложения.

Приложение примерно раз в сутки проверяет наличие нового выпуска. Проверить вручную можно в настройках; при наличии новой версии на главном экране появится кнопка «Обновить». Перед открытием установщика приложение проверяет пакет, номер версии и подпись APK. На эмуляторе проверено обновление с версии 0.1.0 до опубликованной 0.2.0: приложение скачало APK с GitHub, проверило подпись и открыло установщик Android.

## Как проверить приложение на телефоне

На Android-эмуляторе проверены: прямая ссылка на фотографию, видео YouTube, Instagram Reel, фотография и карусель из пяти изображений Instagram, видео и слайдшоу из трёх фотографий TikTok. На реальном телефоне приложение ещё не проверялось.

Также на эмуляторе проверены первый запуск, сохранение настроек после перезапуска и экран выбора при отправке ссылки. Для YouTube экран показывает название, автора, длительность, обложку и доступные форматы. Можно выбрать видео с автоматически подобранным звуком, видео без звука или отдельную аудиодорожку; для аудио показываются язык и признак оригинала, когда они известны. На одном общедоступном ролике проверены файлы с видео и звуком, только с видео и только со звуком. Для публикаций Instagram и TikTok, которые удалось разобрать, экран позволяет отметить нужные фото или видео и показывает миниатюры фотографий. На эмуляторе проверены выбор двух фотографий из карусели Instagram и одного слайда TikTok. Выбор форматов для Instagram и TikTok ещё не реализован.

Если YouTube предлагает дорожку Opus в формате WebM, её можно выбрать в разделе «Только звук». Приложение сохраняет её в папку музыки как OGG без перекодирования. Загрузка такой дорожки проверена на эмуляторе.

В уведомлении о загрузке YouTube доступна кнопка «Выбрать качество», а для Instagram и TikTok — «Выбрать файлы». Они открывают экран выбора для той же ссылки; нажатие на готовый результат по-прежнему открывает файл. На эмуляторе проверены действия всех трёх сервисов и отображение кнопки во время загрузки.

На экране выбора можно задать имя нового файла: расширение подставляется автоматически. Несколько выбранных элементов получают номера, а одноимённые файлы сохраняются отдельно. Имя действует для новых загрузок; уже скачанный файл повторно не загружается. На эмуляторе проверены сохранение фотографии, двух выбранных снимков Instagram и повторная попытка после ошибки.

Полученные сведения временно хранятся в закрытом кэше приложения, чтобы после выбора не запрашивать их повторно. Для Instagram и TikTok кэш содержит временные адреса и только нужные заголовки `User-Agent` и `Referer`; Cookie туда не записываются. Если Android удалит кэш выбранных фотографий или он устареет, приложение предложит выбрать файлы заново.

1. Установите APK и откройте «Скачай». Выберите «Просто» или «Для опытных». Разрешите уведомления, если хотите видеть результат. На Android 8–9 также разрешите доступ к памяти.
2. Откройте в браузере [тестовое изображение](https://upload.wikimedia.org/wikipedia/commons/a/a9/Example.jpg). В меню браузера нажмите «Поделиться» и выберите «Скачай».
3. Дождитесь уведомления «Готово», нажмите на него и проверьте изображение в галерее, в папке «Скачай».
4. Повторите отправку той же ссылки и проверьте уведомление «Уже скачано».

Дополнительно откройте общедоступную публикацию в соответствующем приложении и проверьте через «Поделиться» → «Скачай»:

- видео YouTube и Shorts;
- Instagram Reel, фотографию и карусель;
- видео и фото-слайдшоу TikTok.

Доступность конкретной публикации зависит от ограничений сервиса. Если Instagram не отдаёт исходный файл, запасной вариант может сохранить изображение меньшего разрешения: в одном тесте получена фотография 640×640. При ошибке yt-dlp пробует обновиться и повторить загрузку один раз.

На одном экране выбора можно переключить видео и аудио, задать понятное качество и открыть «Дополнительно» прямо в этом экране. В расширенном режиме там доступны кодек, частота кадров, контейнер, битрейт, точный формат, видео без звука, имя файла, папка, языки субтитров и встраивание миниатюры. По умолчанию приложение сохраняет фото, видео или музыку в папке «Скачай».

В настройках можно выбрать предел качества YouTube от 360p до максимального доступного; «Авто» по умолчанию ограничено 720p. В режиме «Для опытных» доступен максимальный битрейт исходного YouTube-видео: без ограничения или до 1, 2,5, 5, 8 либо 12 Мбит/с. Это фильтр доступных исходных форматов, видео не перекодируется; ручной выбор формата имеет приоритет. Там же доступны способ обработки отправленных ссылок, число одновременных загрузок и соединений, повторы, Wi-Fi only, крупный режим и выбор канала yt-dlp.

Ссылка на отдельное видео внутри плейлиста (например, `watch?v=…&list=…`) скачивает только это видео. Если отправлена чистая ссылка на плейлист, приложение спрашивает подтверждение перед загрузкой всего списка.

В расширенных настройках также можно выбрать от 0 до 5 повторов при сетевой ошибке. Это значение применяется к прямой загрузке и запросам yt-dlp. Отдельная попытка обновить yt-dlp после ошибки по-прежнему выполняется один раз. Число повторов проверено локальными тестами с подставными ответами; изменение и сохранение настройки проверены на эмуляторе.

В разделе «Движок скачивания» расширенных настроек можно выбрать стабильную или ночную версию yt-dlp и нажать «Обновить движок сейчас». Ночная версия получает исправления чаще, но может работать нестабильно. Канал также используется при автоматической проверке и повторной попытке после ошибки. Проверка обновления самого приложения находится отдельно. На эмуляторе проверены установка обоих каналов и скачивание видео после установки ночной версии.

В режиме «Для опытных» откройте «Настройки» → «Диагностика», чтобы увидеть последнюю попытку, время этапов, скорость, объём, оставшееся время и состояние VPN. Кнопка проверки ссылки запускает обычное скачивание и сохраняет файл в галерею. Эти новые показатели проверены модульными тестами и сборкой; замер скорости на физическом телефоне ещё не проводился.

Для YouTube используется встроенный QuickJS из `youtubedl-android 0.18.1`; запросы yt-dlp включают официальный компонент EJS и сохраняют его кэш в приватной папке приложения. Предупреждения yt-dlp о JavaScript runtime и challenge выводятся в «Диагностику» и в скопированный журнал. Проверка работы этого пути на реальном телефоне остаётся частью ручного чек-листа ниже.

При временных ошибках прямой загрузки приложение повторяет запрос с увеличением паузы. Если сервер поддерживает диапазоны и позволяет проверить версию файла, оборванный диапазон продолжается с полученного места в рамках текущей загрузки; если проверка диапазонов отклонена, приложение пробует скачать файл целиком. Возобновление после полного завершения процесса приложения ещё не реализовано. При успешном получении обычной веб-страницы приложение пробует обработать её через yt-dlp. Если сервер сразу возвращает ошибку, показывается уведомление, и yt-dlp не запускается.

## Правила для Instagram и TikTok

Исходные правила находятся в `recipe-defaults/recipes.json` и включены в приложение. Приложение примерно раз в сутки проверяет этот файл в репозитории, проверяет его формат и сохраняет только корректную версию. При отсутствии сети или неправильном файле остаются последние рабочие правила; из файла не запускается программный код. После изменения правил желательно увеличить число `revision`.

Для автоматической загрузки новых правил исходный файл должен быть доступен без входа в GitHub. Встроенные правила продолжают работать без сети. На Android-эмуляторе приложение получило опубликованные правила с GitHub без авторизации. Правила скачиваются только с закреплённого HTTPS-пути этого репозитория, ограничены по размеру и проверяются по схеме; цифровой подписью файл пока не заверяется.

## Автоматические проверки

GitHub Actions для каждого изменения запускает модульные тесты, Android Lint с предупреждениями как ошибками, KtLint, сборку debug/release-вариантов, проверку Compose screenshot previews против эталонов и эмуляторные тесты очереди/уведомлений. Gitleaks проверяет секреты, OSV-Scanner анализирует Gradle-зависимости, а Dependency Review проверяет новые уязвимости в pull request. Dependabot еженедельно проверяет Gradle и GitHub Actions. Подробности и ограничения описаны в [SECURITY.md](SECURITY.md) и [русском отчёте аудита](docs/security-review-ru.md).

Screenshot previews охватывают главный экран, карточку предпросмотра, загрузку выбора, длинные названия, видео/аудио, раскрытые точные форматы, секции настроек и диагностику в светлой и тёмной темах при 100%, 150% и 200%. Снимок «Дополнительно» прокручивается до компактной строки формата, чтобы проверить метаданные и значок совместимости. CI сравнивает снимки с эталонами. После изменения интерфейса обновите их командой `./gradlew updateDebugScreenshotTest`, просмотрите PNG в `app/src/screenshotTestDebug/reference/` на обрезанный текст, перекрытия и интервалы, затем запустите `./gradlew validateDebugScreenshotTest` и добавьте проверенные эталоны в коммит. Сгенерированные PNG сами по себе не доказывают отсутствие дефектов отображения.

## Ручная проверка последней версии

- [ ] Установить APK и открыть «Скачай».
- [ ] При первом запуске пройти три экрана знакомства и выбрать «Просто» или «Для опытных».
- [ ] Проверить цветную иконку приложения на главном экране.
- [ ] На Android 13+ включить тематические значки и проверить системно окрашенную иконку.
- [ ] Проверить белый значок загрузки в уведомлении, которое создало приложение.
- [ ] Проверить название, миниатюру, группировку и действия «Открыть»/«Поделиться» в уведомлениях.
- [ ] YouTube: проверить обычное видео и Shorts, список качества, карточки «Лучшее · m4a»/«Компактное · mp3» с оценкой размера и (по желанию) субтитры.
- [ ] На телефоне проверить выбор качества и аудио с длинным названием и масштабами 150%/200%; убедиться, что верхний заголовок и закреплённая кнопка доступны.
- [ ] Выбрать ограничение 480p на ролике без 480p и убедиться, что берётся доступный вариант ниже; в «Авто» должно остаться выбрано «Авто».
- [ ] В режиме «Для опытных» раскрыть «Дополнительно», выбрать точный формат и видео без звука, затем проверить имя файла, папку, субтитры и миниатюру.
- [ ] Закрепить точный формат и проверить, что его битрейт выбран на ползунке; строки форматов показывают кадры/с, кодек, контейнер, размер и статус совместимости.
- [ ] Проверить `watch?v=…&list=…` (скачивается только видео) и чистую ссылку на плейлист (перед загрузкой всего списка появляется подтверждение).
- [ ] В режиме «Для опытных» выбрать предел битрейта видео и проверить, что автоматический выбор показывает подходящий исходный формат без перекодирования.
- [ ] Instagram: проверить Reel, одиночную фотографию и карусель.
- [ ] TikTok: проверить видео и фото-слайдшоу.
- [ ] Во время загрузки сверить прогресс, скорость, объём и оставшееся время; открыть «Диагностику» и посмотреть VPN.
- [ ] Вставить несколько ссылок и убедиться, что добавляется до 20 загрузок, а повторяющиеся ссылки не дублируются.
- [ ] Добавить ярлык «Скачать из буфера» на главный экран и Quick Settings tile; проверить запуск с одной скопированной ссылкой.
- [ ] В «Недавних» проверить поиск и фильтры «Все», «Видео», «Фото», «Аудио».
- [ ] Выбрать несколько файлов в «Недавних», поделиться ими и проверить удаление с кнопкой «Отменить».
- [ ] В очереди поставить загрузку на паузу, продолжить и отменить; принудительно закрыть приложение и проверить кнопку повтора.
- [ ] В расширенных настройках выбрать папку сохранения и шаблон имени файла, скачать файл и проверить имя/папку.
- [ ] Проверить без интернета, в авиарежиме и при переключении Wi-Fi/мобильной сети.
- [ ] Проверить отказ уведомлений на Android 13+, поворот экрана и повторный запуск после принудительного закрытия.
- [ ] Проверить отмену посреди загрузки и при нехватке свободного места; убедиться, что частичный файл не остался.
- [ ] Проверить обновление APK: сеть → загрузка → SHA-256 → подтверждение установщика Android.
- [ ] Проверить, что отменённые загрузки можно повторить с начала после завершения процесса приложения.

Для YouTube качество можно настроить отдельно. Instagram и TikTok в текущих правилах дают прямой исходный файл без вариантов разрешения; приложение сохраняет его в том качестве, которое отдаёт сервис.

Эти пункты — чек-лист для проверки на телефоне. Локальные модульные тесты и сборка APK не заменяют проверку на физическом устройстве. Системные уведомления браузера, загрузчика и установщика Android используют собственные значки; приложение не может менять их оформление.
